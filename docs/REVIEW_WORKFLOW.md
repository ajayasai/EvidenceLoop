# Evidence import and independent review

This workflow implements the healthcare library's publication boundary. The runtime library is still fictional and nonclinical. Six partial NCCIH text packets are prepared in `evidence/quarantine` for independent review; they are not approved evidence. No qualified reviewer, actual medical approval or clinical publication is supplied or asserted by this repository.

## Roles and configuration

`EvidenceReviewStore` receives an authenticated editor/reviewer identity from the server, never from an untrusted request field. The local demonstration reviewer token is for synthetic operations only. Clinical approvals default to disabled. Editing and review authority must be separately authenticated by the API owner.

To enable clinical review later, the operator must configure a real, independently verified human reviewer in a private server-side registry and enable the clinical workflow. A registry entry contains `qualification_id`, `credential_reference`, `verified_by`, `verified_at`, `expires_at`, `scope: adult_type_2_diabetes_evidence`, and `conflict_disclosure`. Credentials and identity must be established outside the app before configuration; this code does not verify a professional license or manufacture qualification. No request endpoint creates the registry. An expired, changed, missing or wrong-scope record cannot approve or sustain a clinical publication. Identities beginning with `synthetic` or `local-demo` cannot approve clinical evidence.

The editor cannot independently review either their own source import or their own brief. A qualified reviewer approves exact source packet and brief hashes, and declares conflicts. Approval of source material and mappings is never presented as independent review of every generated answer.

## Transaction sequence

1. **Import to quarantine.** Submit a size-bounded source packet through `import_source(editor_identity, payload)`. It includes title, publisher, HTTPS reference URL, source type/date, NFC text with LF line endings, storage rights and permission attestation, source overlap IDs and exact code-point anchors with locators. The service never fetches the supplied URL. Broken anchors, missing rights, unsupported language or invalid lineage fail before publication. A source packet is immutable. Reimporting an identical packet returns the existing version. A new version immediately places that source's runtime trust state under review.
2. **Draft reviewed scope.** `draft_brief(editor_identity, payload)` links immutable source versions, including supporting, limiting, conflicting and context dependencies. An adult type 2 diabetes English brief contains bounded conclusions, outcome-specific effect directions, appraisal method, limitations, a professional question, review due date and exact predicate-to-conclusion mappings. A no-effect conclusion needs explicit rationale beyond statistical nonsignificance. A conflict requires an authored group linking the relevant conclusions and explaining their comparable scope. The software validates references and structure; it cannot establish scientific entailment.
3. **Independent decision.** `review_decision(reviewer_identity, qualification_record, brief_version_id, decision, rationale, expected_hash)` requires current configured qualification, a separate author/reviewer identity and an unchanged target hash. Decisions are `approved`, `changes_requested` or `rejected`; each is immutable. A later adverse decision places dependent sources under review. The reviewer must personally inspect the packet, mappings, exclusions, clinical wording and permissions. A checksum is not that review.
4. **Atomic publication.** `publish(reviewer_identity, qualification_record, brief_version_ids, expected_revision)` locks the publication pointer and source trust rows, rechecks independent approvals/qualifications/due dates, rejects withdrawal and newer unreviewed source versions, validates global IDs and commits one immutable publication plus pointer revision and audit record. A revision mismatch or any failed check rolls back the entire publication.
5. **Runtime use.** `load_current_pack()` revalidates publication, review and source hashes and current qualification before returning an in-process `VerifiedClinicalPack`. A JSON file claiming `clinical_review: true` cannot supply this authority. The domain renderer uses only scoped, reviewed admission rules and authored statements/questions. It preserves action routing, personal suitability, source/anchor versions, every dependency and current trust. A changed publication is rechecked by the API before saving or serving a historical receipt.
6. **Operational withdrawal.** An authenticated editor can use `POST /api/review/sources/{source_id}/withdrawal` with the current `expected_revision` and a bounded reason. This suspends an imported source without asserting medical review. The service locks the publication pointer before the source row, applies compare-and-swap revision control, and records the actor and reason in the immutable review audit. Supporting, limiting, conflicting and context dependencies all block affected receipt saves and check-ins. A clinical reviewer token alone does not grant this editor operation. There is no clinical restore endpoint: correcting the source requires a new immutable import, a new brief and independent approval/publication. The separate synthetic demonstration restore control cannot change clinical source identities.

## Schema and integration contract

The API/bootstrap applies `REVIEW_SCHEMA_SQL` using the database migration identity; the ordinary application role has operational data privileges without schema ownership. `EvidenceReviewStore(store, qualified_reviewers=None, clinical_enabled=False)` uses the existing `store.connect()` and `store.trust()` interfaces. `list_queue()` returns source/brief packets, each source's current trust state/revision, and the current publication pointer for authorized evidence staff. It does not query saved personal cases.

`SourceImport`, `BriefDraft`, `ReviewedAdmission`, `ReviewedPredicate` and `ReviewedOperator` in `services/api/app/review.py` are the exact machine contracts. Version IDs are server-generated UUIDs. Predicate matches bind exact normalized field values; there is no uncontrolled semantic expansion or dose/formulation equivalence. Current mapping coverage is therefore deliberately narrow. Missing mappings produce insufficiency or absent coverage, never an invented medical conclusion.

Review sources, briefs, dependency edges, decisions, publications and review audit records have database triggers rejecting mutation/deletion. Corrections create new versions. Operational trust state is separate and mutable. Publication CAS, source trust locks and exact hashes prevent mixed-version publication; tests exercise these negative paths using a disposable PostgreSQL schema.

## Remaining release requirements

- A real editor and qualified independent reviewer must supply lawful clinical packets and complete the review; there are no seeded approvals.
- Human approval of clinical-facing routing/help wording and the intended use remains separate from source review. Limited engineering sentinels do not establish comprehensive emergency detection.
- Independently labeled clinical evaluation, sentence-support review, source overlap splits, privacy review and performance gates remain necessary before clinical-facing release.
- The default synthetic demo and local test fixtures do not satisfy these requirements. `tests/test_review.py` uses explicitly fictional credentials and text only to verify authorization and transaction behavior, and drops its test schema afterward.
