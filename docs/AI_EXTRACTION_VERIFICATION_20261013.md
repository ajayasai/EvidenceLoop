## Changes under test

- Gemini 3.5 Flash-Lite through the official compatibility endpoint, temperature omitted. Initial runs used minimal reasoning, slot runs through 1.9 used low reasoning, and 1.10 used medium reasoning; none passed fresh validation. Gemini 2.5 Flash-Lite was unavailable to this new account despite appearing in its quota table.
- Provider-specific request schema projection. Inlining references and omitting certain string, array and numeric constraints produced an accepted request. Every response still passes the complete original schema and domain checks. Other providers retain their original wire schema. Projection rejects external/cyclic references and bounds expansion.
- Prompts through `structured-1.11` use required nullable slots and enum-typed classifiers. Literal values are derived from a single quoted phrase; classifiers cite the complete relationship clause. They distinguish analytical roles from grammatical order, assertion polarity from effect direction, named endpoints from generic result placeholders, and hypothetical questions from definite assertions. Ambiguous negation scope or association orientation may remain null. Versions through 1.7 used development examples only; later revisions used inspected validation failures, which became regression data. Version 1.12 further separates source ownership from speech act and requires both an identifiable referent and semantic role before filling a slot.
- One total 10-second extraction deadline includes counting, generation, any schema repair and admission; a repair does not get a fresh deadline. The shared 40-second attempt and token budgets remain in force.
- No automatic paid fallback or semantic repair. Following the resumed trials below, official Gemini extraction permits one bounded 502/503/504 recovery attempt. It shares the existing two-dispatch ceiling with JSON/schema repair, waits one second, retains the failed request's full token reservation, and consumes the original ten-second deadline. Timeouts, quota/access failures and semantic rejection remain terminal. AI evidence alignment remains disabled. Extraction-only assessment may show trusted library context but cannot issue a support/contradiction verdict or saved next step: the current claim schema does not retain enough directional meaning for that comparison.

## Separate evidence-comparison boundary

Code review found that opposite directional claims, such as increasing versus decreasing an outcome, could lose that distinction in the confirmed noun/classification fields. Exact input quotes establish provenance but do not solve this representation gap. The extraction-only compiler path was restricted: it can retain trusted library passages, but clears scientific verdicts, conclusion links, operators, graph warrants, effect judgments, save permission and next steps. It emits `exact_claim_comparison_unqualified` and `alignment_mode: extraction_only`. Existing safety, missing-field and evidence-trust failures remain intact. Replay/manual domain paths are unchanged; broader direction-aware representation and comparison remain release work. No clinical assessment is qualified by this integration.
