## Working local application

The FastAPI backend, built React interface and local PostgreSQL database run together. From the project directory, `scripts/start.ps1` starts the application at `http://127.0.0.1:8765`; PostgreSQL listens only on loopback port 15432. The database is a project process rather than a Windows system service.

The demo supports claim capture, explicit confirmation, bounded assessment and receipt, consent-based save, retrieval, self-reported check-in, a transfer exercise and deletion. The installed working evidence library contains fictional, nonclinical examples. Replay and manual modes are visibly labeled; they do not establish general natural-language extraction or live-model performance.

The updated confirmation screen presents a readable summary with attribution, polarity and separate intent. Corrections are on demand, optional fields and provenance are collapsed, and failed AI extraction has an explicit manual fallback. Users may leave unstated details unknown instead of inventing them; the server can still withhold assessment when context is insufficient.

Persistence includes owner-bound access, CSRF checks, transactions, idempotency and optimistic version checks. Raw unsaved claims stay in expiring memory. Evidence trust is rechecked before display and relevant saved-case actions. The synthetic reviewer workspace can demonstrate withdrawal and the resulting restrictions on an existing receipt. These are implemented engineering mechanisms, not clinical validation.

See [README](../README.md), [architecture](ARCHITECTURE.md) and [demo runbook](DEMO_RUNBOOK.md) for startup, behavior and current limits. Both local and hosted versions are single-process demonstrations. The public service supplies a restricted fictional workflow; durable production operations and cross-device account recovery are not supplied.

The implemented Gemini format uses required nullable extraction slots, exact original quotes and constrained classification enums; the server supplies IDs, offsets and hashes. A conservative admission guard preserves a whole unresolved pronoun in population, intervention or outcome as ambiguous without inventing an antecedent. This guard is separate from the model's extraction accuracy.

The extraction stage defaults to one 10-second deadline covering token counting, generation, any permitted repair and admission; an explicitly configured 10–30-second budget is available under the [prospective protocol](EXTRACTION_30S_PROTOCOL_20261014.md). Alignment has a maximum 14-second stage budget, further limited by the remaining cumulative 40 seconds. Repairs and an opt-in retry for an explicit Gemini length stop share the original stage, token and two-dispatch allowance. Extraction and alignment have independent enablement.

Comparison now requires an unchanged authored fictional replay, verified from its original input hash and semantic fields. Generic manual/live claims and semantically edited replay receive context only, regardless of whether AI alignment is enabled. The current schema cannot establish the exact signed effect from matching nouns. Such receipts have no support/contradiction verdict, effect judgment, supported conclusion IDs, operator claims, claim-support graph, save permission or next step. Safety, unknown-field and trust failures remain intact. Older persisted receipts are also rechecked at read and use boundaries, preserving their immutable historical contents. A configured key or passing mocked transport test does not qualify a model.
