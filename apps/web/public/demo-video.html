This is a recorded screenshot walkthrough with synthetic narration. A convincing claim can leave a person with an unresolved question: what does this finding actually establish, and what should I ask at my next discussion? EvidenceLoop connects that question to its source and keeps the context available when the person returns. Our focus is Healthcare Challenge 2: long-term self-care.

This is a working local engineering prototype. The demonstration uses a fictional fern study, and replay is visibly labeled. It is not a health recommendation or a live model response. We chose this example so you can inspect the behavior without confusing an unfinished clinical evidence library with approved medical advice.

First, the user checks what the claim means. The fictional study describes glow water, fern height, seven days and a plain-water comparison. The user's intention is separate from the words of the claim. Confirmation records the meaning to assess; it does not make the claim true. Unstated information can remain unknown instead of becoming an invented detail.

The receipt keeps the source and its limits inspectable. A finding about one outcome in one setting does not establish a guarantee for every situation. The interface separates the evidence relationship, coverage and intended action. These are bounded demonstration results. A source passage can show where a statement came from; it cannot by itself prove that every inference or personal action is justified.

The next step is an exact question the user can preview. Saving is a separate choice. The screen explains what will be retained, and the save button requires consent. The original pasted text is not stored with the saved record. Now we simulate a later visit. The person chooses to record that they discussed the question. This is labeled a self-report, not verified adherence, improved understanding or a health outcome.

A saved answer must not quietly preserve authority after its evidence changes. These captures show the result of withdrawing a fictional source. When the user reopens the saved receipt, the application checks current source status again. The historical record remains inspectable, but the withdrawn dependency blocks relevant new use. This is a synthetic withdrawal exercise, not a real publisher correction or a claim that we automatically monitor medical literature.

Ambiguous input should not produce confident advice. This fictional sentence does not identify the people, intervention or outcome. The user can clarify what they mean, or leave it unresolved. The application shows its limits. Our live reader remains disabled because no tested model has passed qualification, so this screen is manual fallback, not a staged AI success.

React presents the workflow, FastAPI enforces policy and versions, and PostgreSQL stores consented records and separate evidence-review history. Before save, drafts live in expiring server memory. The optional model can propose structure, but it cannot approve evidence or authorize a write. The application checks quotes, schemas, ownership, consent and current evidence. A local single-process design keeps the prototype small; it does not provide production hosting or cross-device recovery.

WorkBuddy contributed genuine development review. Its Hy3 model examined consent and source-withdrawal code and proposed missing negative tests. Codex corrected and implemented the proposals and ran the local checks: forty-four related tests passed. These captures record the contribution and corrections. WorkBuddy did not run the tests or provide clinical approval.

The evidence is deliberately specific. At the October thirteenth checkpoint, the Python suite passed four hundred ninety-nine tests plus fifty-one subtests. At that checkpoint, a reader probe matched ten of twelve known regression cases and still failed qualification. We have no clinical validation or measured health benefit. EvidenceLoop demonstrates a way to keep meaning, consent and changing evidence connected. The next proof is reliable reading, independent source review and observed use with fictional tasks.
